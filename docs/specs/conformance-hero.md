Status: v1. Python is the oracle (ADR-0004); `vectors/hero.json` is generated by
`tools/h3re/h3re/vectors_hero.py` (`generate()` returns `{"hero.json": ...}`; the lead wires it into
`vectors.generate()` and `EXTRA_VECTOR_MODULES`). Kotlin: `android/sim/src/main/kotlin/h3/sim/hero/Hero.kt`;
tests `HeroTest.kt` (unit) and `HeroConformanceTest.kt` (vectors) in `android/sim/src/test/kotlin/h3/sim/hero/`.
Python side: `tools/h3re/tests/test_vectors_hero.py`. Related: `hero.md` (the behaviour), `conformance.md`,
`conformance-datapack.md`. Synthetic data only (`data/hero_test.json` and packs derived from it).

Regenerate: `cd tools/h3re && python3 -m h3re.vectors_hero --out ../../android/sim/src/test/resources/vectors`.
The vector file is never edited by hand; `test_vectors_hero.py` fails if the committed file differs from a fresh
generation.

## Kotlin API

The package is `h3.sim.hero`, a subpackage on purpose: `adventure.py` also defines `Hero` and `IllegalCommand`,
and `h3.sim.IllegalCommand` (Battle.kt) exists; none may collide.

- `HeroCore.parseHeroPack(decoded)` / `HeroCore.parseHeroPackText(text, what)` = `parse_hero_pack` /
  `load_hero_pack` on file text (floats, NaN and duplicate keys rejected; `what` prefixes loader errors, the
  vectors use `hero.json`). Errors are `h3.sim.DatapackError(category, message)` with the Python text.
  Categories are the `h3.sim.Category` strings plus `HeroCategory.TOTAL = "total"` (a weight total that is not
  positive or is above 2^31-1). Hero uses these: `invalid_json duplicate_key float type unknown_key missing_key
  range length schema_version table empty duplicate_name total`.
- `HeroCore.contentHash`, `stateHash`, `canonical`, `canonicalText`, `stateMap` (the `asdict` tree), `levelForXp`,
  `findClass`, `heroRng(seed, heroId)` (stream `hero:<id>`, `Long` or `BigInteger` seed).
- `HeroCore.createHero(id, classId, content, secondary: List<Pair<String, Long>>, policy)`. Errors are
  `HeroValueError(category, message)` (Python `ValueError`; categories `policy unknown_class unknown_skill
  duplicate_skill bad_level too_many`).
- `HeroCore.apply(state, cmd, rng): HeroApplyResult(state, events)`; `rng` is a `Pcg32` or a `HeroDraw`
  (`range(lo, hi)`, the one draw the core makes; tests use failing and scripted sources). Illegal commands throw
  `h3.sim.hero.IllegalCommand` before any draw.
- Types: `HeroPolicy`, `HeroRules`, `HeroClass`, `HeroContent`, `SecondarySkill`, `SkillOffer`, `Hero`, `HeroState`,
  commands `GainXP(hero, amount: Long)` and `ChooseSkill(hero, index: Long)`, events `XPGained`, `LevelGained`,
  `PrimaryGained`, `SkillOffered`, `SkillLearned`. XP, XP table, weights, amounts and indexes are `Long`; levels,
  skill levels and primary values `Int`; sums use `Math.*Exact`. No floats.

pinned in the test source.

## Out of scope (Kotlin's types cannot express them)

- Python dynamic typing: a `bool` or non-int `amount`/`index` (`GainXP(h, True)` is "XP amount must be a positive
  integer", `ChooseSkill(h, True)` is "no such offer True"); a non-command object ("unknown command"); float,
  non-tuple or malformed (`p[0]` missing) weights in a hand-built class; a non-int or bool skill level, a non-str
  hero id (`str(hero_id)` coerces), class id or skill in `create_hero`; `SecondarySkill` instances passed to
  `create_hero`; a non-str policy value. `test_hero.py` covers `True` and `object()` in Python only.
- Integers beyond `Long`: an amount, index, level or hand-built XP/weight of 2^63 or more (Python rejects them with
  the same messages). Amounts up to `Long.MAX_VALUE` are tested in `HeroTest`.
- Hand-built values beyond `Int` for levels, skill levels and primary skills (Kotlin throws `ArithmeticException`
  at `Int.MAX`; unreachable: it needs a 2^31-entry XP table).

## Known differences (documented, not silent)

- Duplicate-key detection order: `PackJson` (shared with `Datapack.kt`) reports a duplicate key when it sees the
  second key; Python's `object_pairs_hook` runs when the object closes, so a float/NaN after the duplicate in the same
  object is reported first by Python. No vector contains both. (Analysis, not tested.)
- `invalid_json` messages differ (compared by category).
- `PyText.repr` follows Python's `repr(str)` for quotes, backslash, `\n \r \t`, and escapes control, format,
  private-use, unassigned, separator and surrogate code points as `\xNN`, `\uNNNN`, `\UNNNNNNNN`. "Printable" comes
  from the JDK's Unicode tables, Python's from its own; they differ only for code points assigned in one version and
  not the other (none appears in a vector). `PyText.isSpace` is the explicit `str.isspace` set for the BMP (Kotlin's
  `isBlank` differs for U+001C..U+001F and U+0085, both used in vectors).
- Defensive failures that Python raises as `KeyError`, `AssertionError("unreachable")` or `ValueError("empty
  range")` (a skill without a class weight, a draw past the weights, a zero or over-wide span) are unreachable after
  `_check_draw_inputs` and surface in Kotlin as `NoSuchElementException`, `IllegalStateException` and
  `IllegalArgumentException`.
- `Hero.xp` is `Long`: a hand-built XP above 2^31-1 is representable and behaves as in Python (only `GainXP` is refused).

## Mutation check (producer's run, in a private copy; the lead re-verifies)

Each mutation made `gradle --offline :sim:test --tests 'h3.sim.hero.*'` fail; the vector test alone (`HeroConformanceTest`)
also failed for the ones marked V.

`>=` to `>` at `primary_high_from_level` (V); swap of the upgrade and new-skill draws (V); `r < w` to `r <= w` (V);
xp cap check dropped (V); `weighted_pair` pool order news-then-upgrades (V); skills sorted in UTF-16 instead of code
point order (V); classes sorted in UTF-16 order (V); `_check_draw_inputs` skipped (V); weight cap `>` to `>=` in the
guard and in the loader; offers drawn before the primary skill; zero-weight skills offered; `isSpace` without U+0085;
`level_for_xp` with `<`; `offer_fill` ignored; wrong-hero check dropped; `ChooseSkill` index bound off by one;
upgrade allowed above Expert; slot check `<=`; `offer_fill` left out of the hash; `repr` without the quote switch.
