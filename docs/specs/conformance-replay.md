# Conformance: scenario and replay (milestone A5)

Status: v1. Python is the oracle (ADR-0004); `vectors/replay.json` is generated by
`tools/h3re/h3re/vectors_replay.py` (`generate()` returns `{"replay.json": ...}`; the lead wires it into
`vectors.generate()`). Kotlin: `Scenario.kt`, `Replay.kt`; tests `ScenarioTest.kt`, `ReplayTest.kt`.
Related: `replay.md`, `battle-scenario.md`, `conformance.md`. Synthetic data only.

## Kotlin API

- `Scenario.parse(json: String, packs: Datapack): BattleState` is `battle_cli.parse_scenario` plus
  `battle.create_battle` (Battle.kt has no `createBattle`, so it is implemented in Scenario.kt on public
  APIs): placement rows, explicit `pos`, obstacles (sorted, deduplicated), heroes, policy overrides
  (`BattlePolicyPack.policy`), `check_state` caps. Errors are `ScenarioError` with the Python text.
- `Replay.record(scenarioJson, commands, seed, packs, kind): ByteArray`, `Replay.verify(bytes, packs)`
  (returns the header), `Replay.load`, `Replay.info`. Errors are nested classes `Replay.Malformed`,
  `Truncated`, `Tampered`, `UnsupportedVersion`, `UnsupportedKind`, `MismatchedRulesPack`,
  `MismatchedPolicy`, `MismatchedCreatures`, `Diverged` (all `Replay.ReplayError`). The check order is
  `replay.md` section 4. The pack hashes come from `Datapack` (`rules.contentHash`, `policy.contentHash`,
  `packHash`).
- `ScenarioJson` (internal) is the JSON reader: BigInteger integers, last duplicate key wins, floats are
  `Rejected` in replay mode (file order, so a float before a syntax error is `Malformed`, after it
  `Truncated`, as in Python).

## Vector file `replay.json`

| key | content |
|---|---|
| `packs` | `rules`, `battle_policy`, `creatures` file texts and `rules_hash`, `policy_hash`, `creatures_hash` |
| `scenarios` (11) | `name`, `scenario` (text), `seed`, `chooser`, `initial_canonical`, `initial_hash`, `commands`, `replay` (exact file text), `header`. The golden scenario (seed 12345, final hash `fbe9015b...`), the golden scenario under the AI chooser, a hand-made explicit-`pos` scenario, and soak scenarios under default, vcmi-like and the mix-fifo/mix-alt policies |
| `scenario_errors` (69) | `name`, `scenario` (text), `error` (CliError text), `exact` |
| `replay_errors` (50) | `name`, `replay` (text) or `replay_hex`, `error` (class name). Covers all nine classes |
| `truncation` | a small replay; every proper prefix raises `Truncated` |

Kotlin asserts: initial canonical text and hash equal; `Replay.record` bytes equal `replay` byte for byte
and the header equals `header`; `verify` passes; each damaged file gives the named class; every
truncation cut gives `Truncated`; pack mismatch under modified pack texts; record refuses bad input.

## Known differences (documented, not silent)

- Integers beyond 32 bits in a scenario: Python accepts them while parsing and fails in `check_state`
  (`"scenario: stack count out of range"`); Kotlin fails when converting (`"...count out of range"`).
  Both are errors; vectors mark these cases `exact: false` and Kotlin checks only the prefix.
- Command decoding: Python's `decode_command` is `cls(**kw)` and lenient about value types; Kotlin checks
  exact keys (`Attack.from_hex` optional) and integer fields. A file Python records always decodes.
- Invalid UTF-8 outside ASCII: Truncated versus Malformed follows Java's decoder position and may differ
  from Python for exotic byte sequences. Replays are ASCII, so every cut of a valid file is exact.
