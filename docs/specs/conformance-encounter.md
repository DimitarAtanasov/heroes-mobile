# Conformance: encounters and adventure stage E (`h3.sim.encounter`)

Status: v1. Python is the oracle (ADR-0004); `vectors/encounter.json` is generated by
`tools/h3re/h3re/vectors_encounter.py` (`generate()` returns `{"encounter.json": ...}`; the lead wires it into
`EXTRA_VECTOR_MODULES`). Kotlin: `android/sim/src/main/kotlin/h3/sim/encounter/Encounter.kt` plus the Attack hooks in
`h3/sim/Adventure.kt`; tests `EncounterTest.kt` (unit) and `EncounterConformanceTest.kt` (vectors) in
`android/sim/src/test/kotlin/h3/sim/encounter/`. Python side: `tools/h3re/tests/test_vectors_encounter.py`.
Related: `encounter.md` (the behaviour), `adventure.md` section 8, `conformance-adventure.md`, `conformance-hero.md`
(the pattern), `conformance.md`. Synthetic creatures only; the packs are the shipped `data/` files.

Regenerate: `cd tools/h3re && python3 -m h3re.vectors_encounter --out ../../android/sim/src/test/resources/vectors`.
The vector file is never edited by hand; `test_vectors_encounter.py` fails if the committed file differs from a fresh
generation.

## Dependency direction

Python imports `encounter` lazily from `adventure` and `adventure` types from `encounter`. In Kotlin the adventure core
(`Adventure.kt`, package `h3.sim`) knows only an interface, `AdventureEncounterHooks` (`parseSetup`, `checkGame`,
`validate`, `resolve`), and the marker `AdvEncounter` for the state's `encounter` field. `EncounterEngine`
(package `h3.sim.encounter`) implements the hooks and depends on `h3.sim`; nothing in `h3.sim` imports
`h3.sim.encounter`. `Adventure(rules, hooks)` and `AdventureCodec(rules, hooks)` take the hooks (default none).

## Stage E in `Adventure.kt` (what changed there)

- `AdventureCommand.Attack(hero: Int?, target: Any?)`: `target` is a hero id (`Int`), a guard id (`String`) or `null`
  for anything else (bool, float, list, dict; "target must be a hero id or a guard id"); an integer beyond `Int` is
  `hero = null` ("no such hero") or `target = -1` ("no such target hero"), as in Python. `parseCommand` reads it,
  `commandToMap` writes it.
- `AdventureState.encounter: AdvEncounter?` (default null, left out of the canonical form while null, exactly like
  Python's `_OMIT_WHEN_DEFAULT`), and `battles` (already there). The 14-day adventure golden `179c5700...` and
  `adventure.json` are unchanged.
- `AdventureEvent` is no longer sealed (the encounter package adds four events).
- `Adventure.apply` for an `Attack`: "game not started" first, then "battles are not enabled in this game" (Python's first
  check of `encounter.validate`, here because the hooks are optional), then `hooks.validate` (every check, no draw), then
  `hooks.resolve`. An `Attack` on a state with a setup but no hooks is an `IllegalStateException` (configuration error,
  not an `IllegalCommand`). Without hooks `parseState` still refuses `encounter` with the old message.
- `parseState(v, checkEncounter = true)`: Python `check_game` runs last (as in `create_game`); `false` loads hand-built
  states whose armies have no content (the vectors need them to reach `validate`'s content errors).

## Kotlin API

- `EncounterEngine.from(rules: AdventureRules, packs: Datapack)`; `EncounterEngine(rules, battle, battleCodec)`.
  Queries: `battleId(state)`, `battleRng(seed, id)`, `encounterRng(seed, state)`, `streamFor(seed, state, cmd)` (battle
  stream for an `Attack`, `adventure:<game_id>` otherwise; `seed` is a `BigInteger` or `Long`), `buildBattle(state,
  Attack)` (= Python `validate`/`build_battle`), `autoCommand(bs)`, `fight(bs, DrawSource, roundLimit: Long): Fought`,
  `survivors(army, bs, side)`, `battleHash(bs)`, `checkGame(state)`, `parseSetup(json)`.
- Types: `EncounterPolicy(loserFate, slotMapping, roundLimit: Long)` (no defaults in code), `EncounterSetup.of(creatures,
  policy, battlePolicy, rulesHash)` (sorts creatures by name in code-point order, refuses duplicates), events
  `BattleFought`, `ArmyChanged`, `HeroDefeated`, `GuardDefeated` (each has `toMap()`, the Python event as
  `{"type": ClassName, <fields>}`; `BattleFought.log` and `battle_events` are the battle commands and events in
  `BattleCodec.commandToMap` / `eventToMap` form).
- `create_battle` is private in `Scenario.kt`; `Encounter.kt` carries a copy (no obstacles, morale and luck 0). A dedupe
  (make `Scenario.createBattle` internal and share it) is open for the owner of `Scenario.kt`.

## Vector file `encounter.json`

| key | content |
|---|---|
| `packs` | the shipped `rules.json`, `battle_policy.json`, `creatures.json` (text) and their hashes; the Kotlin engine is built with `Datapack.load` from them |
| `constants` | the content-free adventure tables (as in `adventure.json`) |
| `cases` (28) | 836 steps, 500 recorded states, 132 battles (64 won by the attacker, 46 by the defender, 22 stopped by the round limit), 364 refused commands. Per step: `command`, `stream` (`battle` for an Attack, else `adventure`), then `error` (the `IllegalCommand` text) or `canonical`, `sha256`, `events`; for an Attack that built a battle also `battle_sha256` (the initial battle); `rng_after` = `[state, inc]` of the stream used. 7 scripted `GOLDEN_SCRIPT` runs (default, winner_takes_tile, by_slot, round limit 4, alternate battle policy, seed 2027, reversed inputs: the last equals the first), 4 `slow-*` runs (`Begin`, one `Attack` between slow, two-hex and blocking armies: late in the fight a stack can move but no move helps) and 17 playouts |
| `variants` (29) | hand-built states, 2350 Attack attempts (every hero x target pair, ill-typed and unknown ids; 2338 refused, 12 legal): the error text or the hash of the legal result. Rules hash mismatch, missing or wrong-speed content on either side (attacker first), `create_battle` failures wrapped in "battle cannot be set up: ..." (off-grid and colliding placement, by_slot collision, damage range, zero hp, count x dmg_max and count x hp over 2^31-1, defense sum over the cap), removed heroes, other current players, no diagonals, no corner cut |
| `check_game` (16) | hand-built states with `check_game`'s `ValueError` text or null (hero before guard, first bad slot, `%r` of ids and names with quotes, controls, non-BMP and a lone surrogate) |
| `setups` (51) | `EncounterSetup` / `EncounterPolicy` from JSON: error text or canonical form; unsorted creatures, code-point order, duplicates, bad fates and round limits (bool, null, string, list, 0, negative), order of faults (policy, then battle policy, then duplicates), battle policy faults |
| `auto_cases` (502) | battle states sampled from the fights (Begin 110, Move 111, Attack 68, Shoot 20, Defend 193) with the command `auto_command` picks; `stall` marks the 5 states where a stack can move but no move brings its head closer (Defend) |
| `streams` (7) | states with odd game ids and battle counters, seeds beyond 64 bits, the battle id and the first four draws of the battle and the adventure stream |
| `golden` | `hash` `512b53ca...`, day 3, 4 battles, winners `[0, 1, 1, 1]`, rounds and battle hashes |

Playouts: commands come from a plan stream (`derive_stream(seed, "encounter-vec:<name>")`, never Python's `random`):
about half legal attacks, then moves, arbitrary (often illegal) attacks, ill-typed attacks, `EndTurn`; the first step is an
Attack before `Begin`. Games: the golden 8x4 map, a 10x6 map with three players, 7/5/3/1-slot armies, flyers, shooters,
two-hex units, water and rock (`zoo`), two speed-0 armies (`draw`: only the round limit ends the battle, 3 and 100),
and non-BMP creature names and guard ids (`unicode`, game id `gé` + U+1F600). Policies: both loser fates, both slot
mappings, round limits 1, 3, 4, 100, two non-default battle policies (speed tie, wait order, row offset, edge columns,
range origin, defend bonus), seeds negative and beyond 64 bits.

Kotlin asserts: pack hashes; every recorded state parses and re-encodes to the same canonical text and hash (stage A);
every step replays from the previous recorded state: initial battle hash, error message, untouched state and stream for an
error, canonical text, hash, events (canonical text, so the whole battle log and event list) and the stream position after
(stage B); every variant attempt; `check_game` messages; setup construction; `auto_command` per sampled battle state;
battle ids and stream draws; the golden run replayed from the initial state with the hash pinned in the test source.
`EncounterTest` adds what JSON cannot say: float, bool and list targets, the hook-less cores, a null stream, the battle
counter at `Int.MAX`, the log replayed on the named stream, round limits, survivors, removed heroes, winner_takes_tile.

## Out of scope / known differences (documented, not silent)

- Python dynamic typing: a non-command object ("unknown command"), an `int` subclass, a non-`EncounterSetup` in
  `encounter` ("encounter must be an EncounterSetup"), non-`Creature` entries. Floats and bools are covered as "not a
  hero id or guard id" (bool in the vectors, `Double` in `EncounterTest`).
- `round_limit` is a `Long`: Python accepts any int. A value of 2^63 or more is refused by `EncounterPolicy.parse`
  ("round_limit beyond 2**63-1 is not supported"). Values to 2^62 are in the vectors.
- The battle counter is an `Int`: an `Attack` at `battles = 2^31-1` throws `ArithmeticException` before any draw
  (state and stream untouched); Python continues. The battle id uses a `Long` and matches Python at that edge.
- Numbers beyond `Int` in a hand-built setup (creature stats, `placement_rows`) or army (count, speed): Python builds the
  state and refuses the `Attack` with a "battle cannot be set up: ... out of range" text; Kotlin refuses the state at
  parse time (`BattleJson.int`). The caps that fit in `Int` (count x dmg_max, count x hp, the defense sum) are in the
  vectors and give the Python text.
- An army of more than 7 slots (Python `IndexError` for by_slot, "each side needs 1..7 stacks" otherwise): `parseState`
  refuses such armies (as `create_game` does).
- Battle policy fault texts come from `BattleCodec.policyFrom` and match Python for every fault in `setups` (the faults
  beyond `Int` range are not in the vectors: Kotlin refuses them while reading the number).
- A JSON float in `round_limit` is refused by the vector reader and by `EncounterPolicy.parse` (not an int).

## Mutation check (producer's run, in a private copy; the lead re-verifies)

36 mutations, each applied alone to `Encounter.kt` (33) or `Adventure.kt` (3), each made `gradle --offline :sim:test
--tests 'h3.sim.encounter.*' --tests h3.sim.AdventureTest` fail; the sources were restored (diff against the original) after
each. The first run left one survivor (`gap <` to `<=` in `autoCommand`: no sampled battle had a stack that can move but
not get closer); the `slow-*` runs and the `stall` auto cases were added, and the full list was re-run: 36 of 36 caught.

Rules hash check dropped; hero index bound off by one; own-hero check dropped; self-target check dropped; adjacency check
dropped; by_slot column ignoring the two-hex shift; defender stack set-up before the attacker's; auto-combat tie takes the
last of equal expected damages; auto-combat Attack/Shoot key swapped; move tie-break by row first; no-progress test `<=`;
nearest-enemy gap as `maxOf`; round limit `>=`; reported rounds not capped; dead slots kept; `ArmyChanged` always emitted;
defeated hero keeps its movement points; winner_takes_tile for a defending winner; its `HeroMoved` mp_left 0; defeated
guard not removed; battle counter not incremented; creature speed not compared; creatures sorted in UTF-16 order;
`check_game` skipping guards; `round_limit` 0 accepted; battle id off by one; an Attack on the adventure stream; placement
collision unchecked; foe hero `null` instead of `Hero()`; duplicate creature names accepted; battle hash of the initial
state; defender survivors read from the attacker side; defender events before the attacker's; "battles are not enabled"
check dropped (`Adventure.kt`); `encounter` left out of the canonical form (`Adventure.kt`); an integer target beyond `Int`
read as hero 0 (`Adventure.kt`).
