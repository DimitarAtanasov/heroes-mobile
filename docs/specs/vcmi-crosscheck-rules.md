# VCMI cross-check of `rules.md` / `battle.md` uncertain items

Status: research note, 2026-11-01. Inputs: `docs/specs/rules.md` (§2–§6 and the §9
checklist), `docs/specs/battle.md` §8 (BattlePolicy table),
`tools/h3re/h3re/rules.py` and `tools/h3re/h3re/battle.py`.

Reference: the VCMI engine (GPL-2.0-or-later), a read-only clone at
`/home/user/vcmi/vcmi`, revision `c53e0e8` (develop branch). **Licence rule:** this
file records only functional facts and constants, in our own words, each with a
citation (VCMI path plus a short description of where the fact lives). No VCMI code
is copied or paraphrased here, and none may be copied into our code. VCMI is a
reimplementation, not the original game. Where VCMI and our documented sources
disagree, VCMI is evidence, not proof. The §9 experiments in `rules.md` still decide
the matter.

Confidence legend:

- **clear**: VCMI implements this unambiguously (code plus config agree).
- **ambiguous**: VCMI has the behaviour, but it might be a VCMI simplification, the
  code and comments disagree, or the original's behaviour is still in doubt.
- **VCMI-differs**: VCMI deliberately departs from the original game (it says so in a
  comment or makes it a setting with a non-H3 default). Do not copy it.

Hex notation below: VCMI numbers hexes `row * 17 + col`, with row 0 at the top. We
write `(col,row)`, as `battle.py` does.

## 3. Items VCMI does not settle

- **Tactics deployment** rows: VCMI uses a tactic-distance zone (`lib/battle/CBattleInfoCallback.cpp`, `isInTacticRange`) rather than a row table. Out of scope for `battle.py`.
- **Obstacle placement algorithm**: [engine] for us. VCMI's version is server-side and data-driven (`config/obstacles.json`). Do not copy it.
- **Marketplace rates**: VCMI uses an effectiveness table indexed by the number of marketplaces owned, capped at 9 (`lib/mapObjects/IMarket.cpp`). The values are content data; record them from our own sources.
- **Original-game truth** for #5, #6, #7 and #10: VCMI's choices are consistent and deliberate, but nothing in the code proves they match the original. Run the §9.1, §9.4 and §9.12 experiments plus a new bad-morale-rate experiment before changing documented defaults. #1 (row parity) is different: the original's grid has one fixed parity, and VCMI's code and renderer agree on it. Our default is a pure convention choice, so switching to `"even"` costs nothing beyond re-pinning the golden hash.
