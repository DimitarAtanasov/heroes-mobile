# Conformance: town core (`h3.sim.town`)

Status: v1. Python is the oracle (ADR-0004); `vectors/town.json` is generated by
`tools/h3re/h3re/vectors_town.py` (`generate()` returns `{"town.json": ...}`; the lead wires it into
`vectors.generate()` and `EXTRA_VECTOR_MODULES`). Kotlin: `android/sim/src/main/kotlin/h3/sim/town/Town.kt`;
tests `TownTest.kt` (unit) and `TownConformanceTest.kt` (vectors) in `android/sim/src/test/kotlin/h3/sim/town/`.
Python side: `tools/h3re/tests/test_vectors_town.py`. Related: `town.md` (the behaviour), `conformance.md`,
`conformance-datapack.md`, `conformance-hero.md` (the pattern). Synthetic data only (`data/towns_test.json` and packs
derived from it).

Regenerate: `cd tools/h3re && python3 -m h3re.vectors_town --out ../../android/sim/src/test/resources/vectors`.
The vector file is never edited by hand; `test_vectors_town.py` fails if the committed file differs from a fresh
generation. The golden hash `0360ce88...` and the growth digest `b4108c58...` (town.md section 7) are not moved by this
port; both are asserted in `TownTest` and `TownConformanceTest` as literals.

## Kotlin API

The package is `h3.sim.town`, a subpackage on purpose with its own `Resources`, `GrowthPool` and `IllegalCommand`:
`Adventure.kt` (`AdvResources`, `AdvGrowthPool`), `Battle.kt` (`h3.sim.IllegalCommand`) and `h3.sim.hero` have
neighbours; none may collide. Wiring the town core to the adventure core (town.md section 5) is a later layer and maps
`Resources` to `AdvResources` and `GrowthPool` to `AdvGrowthPool` field by field.

- `TownCore.parseTownPack(decoded)` / `TownCore.parseTownPackText(text, what)` = `parse_town_pack` /
  `load_town_pack` on file text (floats, NaN and duplicate keys rejected; `what` prefixes those two errors, the vectors
  use `towns.json`). Errors are `h3.sim.DatapackError(category, message)` with the Python text. Categories are the
  `h3.sim.Category` strings plus `TownCategory` (`unknown_building upgrade cycle player_unique dwelling horde`). Town
  uses `invalid_json duplicate_key float type unknown_key missing_key range length schema_version empty
  duplicate_name` from `Category`.
- `TownCore.contentHash`, `stateHash`, `canonical`, `canonicalText`, `stateMap`, `contentMap`, `townRng(seed, gameId)`
  (stream `town:<id>`, `Long` or `BigInteger` seed), `findBuilding`.
- `TownCore.createGame(gameId, content, players: List<Resources>, towns: List<TownSetup>, policy)` and
  `TownCore.createGameChecked(gameId: Any?, content, players: Any?, towns: Any?, policy)`. The checked entry is the
  one implementation; it takes arguments of any decoded type (`BigInteger`, `Boolean`, `String`, `List`, `Map`,
  `null`; `Resources`/`RawResources` for treasuries, `TownSetup`/`RawSetup` for towns) and applies Python's
  `type(v) is int` strictness: a bool, a string or `null` where an int belongs, a treasury field outside
  `0..2^31-1`, a non-string id, are all `TownValueError` with the Python message. The typed `createGame` calls it.
  `str(game_id)` is reproduced (`5` is `"5"`, `None` is `"None"`, `True` is `"True"`, lists and dicts as their repr).
- `TownCore.apply(state, cmd, rng: Pcg32? = null): TownApplyResult(state, events)`. Nothing is random: `rng` is never
  touched (the tests compare the stream position before and after every step, legal or not). An illegal command throws
  `h3.sim.town.IllegalCommand` (an `IllegalArgumentException`) before anything changes.
- Queries: `missingRequirements`, `activeBuildings`, `townIncome`, `playerIncome`, `dwellings`, `growthPools(state,
  town, current)`, `weeklyGrowth(base, (num, den), horde, policy)`, `roundCastleBonus` (the one rounding step).
- Errors by Python class: `IllegalCommand` (also raised by queries for an unknown town), `TownValueError` (`ValueError`:
  `TownPolicy`, `createGame`), `TownKeyError(key)` (`KeyError`; `message` is `repr(key)` as `str(KeyError)`; raised by
  `findBuilding`, `missingRequirements`, and by any query or `Build` that reaches a town whose faction the content
  lacks), `ArithmeticException("Fraction(n, 0)")` (`ZeroDivisionError`, a zero denominator in `weeklyGrowth` or in a
  hand-built `growth_bonus`).
- Types: `TownPolicy`, `Building`, `Faction`, `TownContent`, `TownSetup`, `Town`, `TownState`, `Build(player, town,
  building)`, `NewDay`, events `BuildingBuilt`, `TownDayStarted`. Amounts, costs, growth, owners, players and the day
  are `Long`; levels `Int`; sums and products use `Math.*Exact`. No floats.

## Vector file `town.json`

| key | content |
|---|---|
| `packs` (7) | valid pack texts by name: `test` (`data/towns_test.json` verbatim), `tiny`, `unicode` (astral, BMP-high and accented ids), `bigvalues` (costs, income, growth, hordes and bonuses at 2^31-1), `twin` (two unrelated buildings with one `player_unique` tag), `minimal`, `seven` (one building per resource) |
| `pack_valid` (33) | `name`, `text`, content `hash`, `factions` (ids), optional `same_hash_as` (key order, whitespace, escapes, faction/building/requires order, explicit defaults never change a hash; `[2,4]` is not `[1,2]`); values at the cap, 60-deep chains |
| `pack_invalid` (242) | `name`, `text`, Python `message`, `category`. Every rejection in `parse_town_pack` and its helpers, check order (building 0 before building 1, one faction before the next, syntax before semantics, unknown reference before upgrade rule), floats/NaN/Infinity, duplicate keys, bad JSON, ids reported in code point order |
| `policies` (20) | `citadel_rounding`, optional Python `message` (quotes, control and astral characters in the repr) |
| `weekly_growth` (1233) | `base`, `bonus`, `horde`, `mode`, `result` or `error` `{kind, message}`: a sweep of 16 fractions x 24 bases x 3 modes, the loader's extremes (products near 2^62), negative operands (Python floor division), zero denominators |
| `streams` (54) | seed (incl. negative and beyond 64 bits), game id (incl. empty, `:`, non-ASCII), stream `state`, five draws, `after` |
| `create` (204) | a `create_game` call as descriptors (below) with policy; state `hash` and `canonical` text, or `error` `{kind, message}`. Every `ValueError` branch, rejection precedence, one case per resource field per bad type (bool, string, null, negative, cap+1, beyond 64 bits, list, dict) |
| `traces` (74) | `create` arguments, `seed`, `initial_hash`, `initial_rng`, `initial_queries`, `steps` (2475): `cmd`, then `events` and `queries` (after a legal step) or `error`, `hash`, `rng`; `final_canonical`, `final_queries` |
| `queries` (28) | a built state (canonical tree), one query, `result` or `error` |
| `states` (82) | hand-built state (canonical tree), its `hash`, `seed`, `rng_before`, optional `cmd` then `events`, `hash_after`, `canonical_after`, `queries_after`, or `error`; `queries` on the state before; `rng_after` |
| `golden` | town.md section 7: state hash `0360ce88...`, growth digest `b4108c58...`, content hash `629836f9...`, 24 events, day 8, pools, the digest's three rounding runs |

Descriptors (`create`, `traces`): `players` is a list of `{"res": [seven values]}` (a `Resources` whose fields may have
any JSON type) or `{"raw": v}` (any other value), or `{"raw": v}` as a whole; `towns` is a list of `{"setup": {id,
faction, owner, built}}` or `{"raw": v}`, or `{"raw": v}` as a whole. The Kotlin test maps them to `RawResources`,
`RawSetup` and raw values, and for the successful cases also builds the typed arguments and compares hashes.

Query records: `{"fn", "args", "result" | "error"}` for `active_buildings`, `town_income`, `dwellings`,
`growth_pools` (args: town, `current` as `[[id, available, growth]]`), `missing_requirements`, `player_income`.
`growth_pools` is called with a `current` holding a junk id and a repeated id (the last entry must win).

Traces (random plans drawn from `derive_stream`, never Python's `random`): 54 random on the test pack (3 town layouts
x 3 treasuries x 3 rounding modes, 45 steps), 6 on `tiny`, 3 on `unicode`, 2 on `twin`, 3 on `bigvalues`; scripted
traces: every building of every town built in dependency order (five packs, default and `nearest`), exact money and one
short on each of the seven resources, one build per town per day (not per player), one capital per player over all
towns and inside one town and across factions, forty days, growth with several castle-bonus sources, hordes and carried
pools. 1074 of the 2475 steps are illegal commands (unknown player/town/building, `-1`, `2^40`, wrong owner, built
today, missing requirements, second capital, cannot afford); each records the unchanged hash and stream position.

`states` covers what the loader and `create_game` refuse but a saved or hand-built state can hold: a town whose faction
the content lacks (`IllegalCommand` "no such building" from `Build`, `KeyError` from queries, and `KeyError` escaping
`Build` through `_unique_count`), duplicate town ids (a build goes to every town with that id; income and queries use the
first), two active dwellings of one level (two pools with one id, creature order by code point), horde bonuses without
a dwelling or negative, unsorted or duplicated `built`, ids in `built` the faction lacks, `built_today` preset, owners
outside the player range or negative, no players, negative and above-cap treasuries, negative costs, day 0, negative and
2^40, growth bonuses that tie, are negative, have a negative denominator, are huge or have a zero denominator.

Kotlin asserts: pack hash, faction/building ids; error category and message (`invalid_json` by category only, the parser
texts differ); `create` hash and canonical text, and error class and message; stream state and draws; per trace step the
events (canonical text), the queries, the state hash and the stream position, and that an illegal step changes neither;
hand-built states (canonical text round trip, hash, events, hash after, queries before and after, stream after); the
golden run with both hashes pinned in the test source.

## Out of scope (Kotlin's types cannot express them)

- Python dynamic typing outside `create_game`: `Build.player` is `Long` (Python: a `bool` or non-int player is "no
  such player True"), a non-str town or building id in a command, a non-command object ("unknown command"), a float or
  non-int in a hand-built state, `Fraction` or `Decimal` growth bonuses, a non-`TownPolicy` policy object.
  `test_town.py` covers floats, bool and int subclasses in Python only. `create_game`'s own strictness is covered
  through `createGameChecked` for everything JSON can carry (floats cannot: vectors never hold them).
- Integers beyond `Long`: a hand-built treasury, cost, income, growth, owner or day of 2^63 or more; `weeklyGrowth`
  with a base, horde or fraction whose exact product leaves `Long` (Kotlin throws `ArithmeticException`, Python's ints
  grow). Everything the loader or `createGame` can produce (all pack integers and treasuries at most 2^31-1) fits;
  the extremes are in the vectors and in `TownTest` against a `BigInteger` oracle. `NewDay` at `Long.MAX` throws
  `ArithmeticException` and leaves the state.
- Lone surrogates in a JSON string (Python keeps them; they cannot be UTF-8 encoded for the stream name).

## Known differences (documented, not silent)

- `invalid_json` messages differ (compared by category). Duplicate-key detection order follows `PackJson` (see
  `conformance-hero.md`); no vector holds both a duplicate and a float in one object.
- `TownText.repr` follows Python's `repr(str)` for quotes, backslash, `\n \r \t`, and escapes control, format, private-use,
  unassigned, separator and surrogate code points as `\xNN`, `\uNNNN`, `\UNNNNNNNN`; the Unicode 15.1 additions are
  patched in, as in `Adventure.kt` (JDK 21 has Unicode 15.0). "Printable" otherwise comes from the JDK; the vectors hold
  no code point assigned in one table and not the other. `TownText.blank` is the explicit `str.isspace` set.
  `TownText` is a copy of the helpers in `Adventure.kt` and `hero/Hero.kt`, kept local so the three ports stay
  independent; folding them into one shared object is a later cleanup.
- Defensive failures Python raises as `KeyError` from inside helpers are mapped to `TownKeyError` with the same key;
  the `Build` path converts them to `IllegalCommand("no such building ...")` exactly as Python's `except KeyError`.
- `weeklyGrowth` reduces the fraction first (Python `Fraction(*bonus)`); the result equals the unreduced one, the
  reduction only matters for overflow headroom and for the `Fraction(n, 0)` message.
